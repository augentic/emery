## 0.38.0

Unreleased

### Added

- The `specify` re-mine diff flags a changed preamble: `SpecDiff` / `DesignDiff` carry `preamble: bool`, the JSON envelope carries it per document, and text mode prints `spec.md ~ preamble` / `design.md ~ preamble`.
- `emery_sdk::Seam::Files(files)`: files beneath the input's root, named relative to it, as one seam. The SDK lends the files' common ancestor — a per-directory seam is enforced by the grant — and lists the files relative to it in the turn; only a set sharing no directory lends the root with every path stated. The paths are sorted and deduped; one that escapes the root is `bad_request`, a set naming no file is `bad_request`, and `Files` over an inline value is `server_error`.
- `emery_sdk::mine(model, ctx, docs, seams)`: the extraction an adapter's `extract` calls — one gated model turn per seam under `prompts/extract.md` among `docs`, at most four pending, joined into one `Evidence` document with each seam's anchors re-rooted under what it was lent. `emery_sdk::metadata(kind)`: the `metadata` answer, the adapter's kind beside the SDK's own version as the `emery-version` pin. `emery_sdk::extract(id, input, docs, survey)`: the `extract` answer, which surveys, mines over `WasiModel`, and lowers onto the world's `evidence` and `error`. `emery_sdk::export` is the `source-adapter` world's `Guest`, its records, and `export!`, which an adapter's guest names directly.
- `emery-sdk` re-exports what adapter-side code names from the leaves: the contract's `Source` capability (`emery_sdk::Source`, for a program that calls an adapter the way the engine does — an adapter implements the world's `Guest`, never `Source`), and the embedded prose — `emery_sdk::Doc`, `emery_sdk::include_prose!("../prose")`, and the `emery_sdk::prose` lookups (`body`, `find`). An adapter's `[dependencies]` is `emery-sdk` alone, and it has no `[build-dependencies]`. The mock adapter and the SDK's suites name `emery_sdk::Doc`.
- `emery_sdk::survey`, the mechanical half of a tree adapter's survey: `files(root, keep)` lists the regular files beneath a root, sorted and named relative to it, asking `keep` about every entry (`survey::Entry::Dir` prunes a directory, `File` selects a file) and never offering the engine's own files — `.omnia/` directories and `spec.md` / `design.md` wherever they appear; `by_directory(files, floor)` cuts the list into one group per top-level directory holding at least `floor` files, in directory order, and folds the root's own files and every smaller directory into one sorted remainder. `Seam` derives `PartialEq`, so an adapter's suite can assert its survey.
- `emery_sdk::survey::by_model(model, ctx, docs, files, floor)`, the model half of a survey: one call, before any seam is mined, that cuts `files` by what they serve rather than where they sit. The adapter's `prompts/survey.md` among `docs` is the system prompt; the turn names the adapter and source, lists every candidate file, states the floor, and lends the input's root; the `list_docs` / `read_doc` tools answer from `docs`. The answer is a `survey::Partition { groups: Vec<Group { name, files }> }` — the shape a survey prompt's worked example must parse as — checked whole: a group naming no file, a file not among those offered, or a file in two groups goes back as findings and the backend asks again. The accepted groups come back in answer order, each sorted; a group of fewer than `floor` files folds, with every file the model left out, into one sorted remainder last, so coverage is total and the model chooses only the grouping. A missing prompt or an inline value is `server_error` before any turn; a tree with no files spends none and cuts into nothing; spent rounds are `bad_request` carrying the last findings, as an evidence call's are.

### Changed

- Extraction is `emery_sdk::mine(model, ctx, docs, seams)`, called from an adapter's own `extract` with the seams its survey chose. It puts each seam to the model as one turn, at most four pending and yielded in seam order, then joins the partials into one document: claims concatenated in seam order, each seam's `path` anchors and `Backing::Path` re-rooted under what it was lent. Every seam is waited for; the failures are then reported together, each as `- seam <index>: <description>` in seam order, under the first failure's class. No seam is `bad_request` before any is mined. One seam is a single turn and its outcome, unchanged. The turn itself — the embedded `prompts/extract.md` as the system prompt, the SDK's brief, the lend, and the claim gate as the check — is the SDK's alone: there is no per-seam hook to call or override, so the seams an adapter hands over are its one way to shape what the model is asked. A survey that asks the model takes it, through `survey::by_model`; a mechanical survey is a plain fn over the call's `Context`, and an adapter's suite asserts it with no model at all.
- The SDK is types and functions, the shape of omnia's own guest SDK, and an adapter is a guest of the `source-adapter` world: it implements the world's `Guest` from `emery_sdk::export` on a unit type, invokes `export::export!` for it, answers `metadata` with `emery_sdk::metadata(SourceKind::..)`, and answers `extract` with `emery_sdk::extract(id, input, docs, survey)` — the survey an async closure over the call's `&Context` returning the seams; the SDK lifts the input (`SourceInput::from`), builds the `Context`, hands the seams to `mine` over `WasiModel`, and lowers the outcome onto the WIT `evidence` and `error`. The guest module is `cfg(target_arch = "wasm32")`, so the crate builds natively and its survey is tested there.

- The `Authority` enum is `SourceKind`, the kind of source an adapter reads (`intent`, `documentation`, `behaviour`); "authority" names the precedence those kinds rank by, not a type. An adapter names it in its `metadata` answer through `emery_sdk::metadata`, and a committed requirement's loser notes record it as `kind` — a revision-shape change, so every revision re-ids. The kebab values and the rendered `Note:` lines are unchanged.
- The kind of source is the adapter's metadata, not the document's. The WIT `adapter-metadata` record gains `kind: source-kind` and the `evidence` record is `claims` alone; `emery_adapter::source::AdapterMetadata` gains `kind: SourceKind` and `Evidence` is `{ claims }`, deriving its answer schema with `deny_unknown_fields`, so a document-level `kind` in a model answer is a schema miss the backend corrects. `emery_sdk::metadata(kind)` reports the adapter's kind beside the `emery-version` pin, and the SDK's per-seam turn asks `Question::<Evidence>` directly. `adapter::load` returns each distinct adapter's declared kind keyed by id (`BTreeMap<String, SourceKind>`) from the one `metadata` read that also gates its version, and `specify` ranks every source by it before the fan-out — so an adapter's rank is fixed at load, never read from what the model returned. Committed revisions are unchanged: the loser `kind` a requirement records is the same value, sourced from the adapter.
- `emery-prose` is named for what it does: the `registry` module is gone and `Doc`, `find`, and `body` sit at the crate root; the `registry!` macro is `include_prose!`, after `include_str!` — a procedural macro (`emery-prose-macros`, reached only through `emery_prose::include_prose!`) that takes the tree as a path relative to the invoking file and expands to the `&'static [Doc]` itself, sorted by path with every relative link checked, so an adapter reads `static DOCS: &[Doc] = emery_sdk::include_prose!("../prose");` inside its guest module. There is no `emit` feature, no build-script walker, and no generated `docs()` accessor: a crate's `build.rs`, when it keeps one, prints `cargo::rerun-if-changed=prose` alone, so a document added to or removed from the tree rebuilds it. `emery_prose::body` returns `Option<&'static str>` instead of panicking on a path the build did not embed — the SDK reads the extraction prompt from the table for each seam's turn and reports a miss as `server_error`.
- The contract and SDK crates are renamed for what they hold. The contract crate is `emery-adapter`, after the `emery:adapter` WIT package it binds, with one public module per axis: `emery_adapter::source::{Source, SourceInput, SourceContent, SourceKind, AdapterMetadata, Evidence, Claim, ClaimKind, Backing, CLAIM_ID_REGEX}` (and, on `wasm32`, `export` — the world an adapter's guest implements, which the SDK re-exports), with the shared kebab predicate at the root (`emery_adapter::is_kebab`). The SDK crate is `emery-sdk`: adapters `use emery_sdk::{Context, Seam, mine, …}` and `emery_sdk::export`; its root stays flat. There is no `emery-source` crate. A second axis lands as a second module in each crate, not a crate.
- The contract crate exposes every public item of an axis from its axis module; the `types` and `claims` modules are gone, as are the test-only `SourceInput::workspace` / `SourceInput::value` constructors.
- `emery_sdk::Context` is `{ adapter_id, input }`; `EvidenceTurn`, `content_note`, and the `types` module are deleted; the crate re-exports the contract's types at its root and omnia's `model` module in place of fourteen individual model types.
- The SDK's user turn always offers the `list_docs` / `read_doc` reference tools (every adapter embeds at least its prompt) and describes a bound workspace as "the source tree the prompt walks". The turn names the source by adapter id and key alone; what kind of source it is, the adapter's own `prompts/extract.md` says, so the SDK carries no source noun.
- `specify` checks its source list whole — non-empty, kebab-case keys, no key twice, roots beneath the project — before a single adapter loads, so a refused list never fetches a package or reads a component.
- An adapter's identity is its reference. `AdapterRef`'s `Display` / string conversion — a bare name, a project-relative component path anchored where it was written, or a `<namespace>:<name>@<version>` package reference — is what the plugin loader registers the adapter under and what the `Source` capability dispatches to; `AdapterRef::name`, `AdapterRef::id`, and `adapter::Loader` are gone: `adapter::load(provider, adapters)` takes the references a run's sources name, loads every distinct adapter once — all together, so a run waits only for its slowest acquisition — and reads each one's `metadata` once, however many sources share it — the `emery-version` gate, and the kind of source it returns keyed by adapter id. The `source:<name>` routed id is gone with them: a bare `intent` dispatches to the deployment's guest `intent`, and a local component is registered under its path, so two files sharing a stem are two adapters rather than one. The kebab stem a command-line adapter is keyed by when the operator names no key (`emery_intent.wasm` → `intent`) is the CLI's rule, beside the argv decoder in `crates/cli/src/sources.rs`.

### Removed

- `emery_sdk::SourceAdapter` and the `source!` macro are gone, and with the trait its `extract`, `evidence`, `prompt`, `metadata`, and `stamp`. An adapter's `extract` is its own `Guest` method over `emery_sdk::extract`; its `metadata` is `emery_sdk::metadata(SourceKind::..)`; the `doc(hidden)` on `export`, which the macro expanded against, is lifted. `emery_sdk::Answer` is gone too: the model answers the contract's `Evidence` directly, and there is no kind to stamp onto it — the engine takes it from the adapter's metadata.
- The per-source `digest` pin (`SourceConfig.digest`, `[[source]] digest`) is gone. A local component or exact package reference loads without a content hash; a `digest` key in `emery.toml` is an unknown field.
- The per-source `registry` override (`SourceConfig.registry`, `[[source]] registry`) is gone: which registry serves a package is the deployment's policy, not a project file's, so no `emery.toml` can redirect the binary. The shipped runtime resolves a package's namespace through a wasm-pkg client configuration compiled in beside its default endpoint (`src/wasm-pkg.toml`, the schema of `wkg`'s own config, embedded by `src/main.rs` as `{ registry: "omnia.host", config: include_str!("wasm-pkg.toml") }`); `emery:<name>@<version>` routes to `augentic.io`, anything unmapped to `omnia.host`. Every package load carries `Location::Registry(None)`; a `registry` key in `emery.toml` is an unknown field.
