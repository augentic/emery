## 0.38.0

Unreleased

### Added

- The `specify` re-mine diff flags a changed preamble: `SpecDiff` / `DesignDiff` carry `preamble: bool`, the JSON envelope carries it per document, and text mode prints `spec.md ~ preamble` / `design.md ~ preamble`.
- `emery_sdk::Seam::Files(files)`: files beneath the input's root, named relative to it, as one seam. The SDK lends the root — the read-only mount is the boundary — and lists the files relative to it in the turn as the only ones to mine, sorted and deduped with `.` and empty segments dropped; one that escapes the root is `bad_request`, a set naming no file is `bad_request`, and `Files` over an inline value is `server_error`.
- `emery_sdk::extract(ctx, docs, seams)`: the extraction an adapter's `extract` calls — one gated turn per seam, put to the model `ctx` carries under `extract.md` among `docs`, at most `emery_sdk::CONCURRENT` (four) pending, joined into one `Evidence` document in seam order; every seam of a workspace is lent the root, so every anchor is root-relative as answered and nothing is re-rooted. `emery_sdk::metadata(kind)`: the `metadata` answer, the adapter's kind beside the SDK's own version as the `emery-version` pin, a target-neutral `AdapterMetadata`. `emery_sdk::source_adapter!(metadata, extract)`: the one macro an adapter's guest invokes, in the shape of omnia's `command!(entry)` — it implements the world's `Guest` on a private type and invokes the bindings' `export!` for it over two plain fns the adapter writes: `fn metadata() -> AdapterMetadata` and `async fn extract<P: Model>(ctx: &Context<'_, P>) -> Result<Evidence, Error>`; the SDK lifts the WIT input and the host's model onto the `Context` before the call and lowers the outcome onto the world's `evidence` and `error` after, so no adapter names a binding or a backend. `emery_sdk::export` — the world's `Guest`, its records, and `export!` — stays public for a guest written by hand.
- `emery-sdk` re-exports what adapter-side code names from the leaves: the contract's `Source` capability (`emery_sdk::Source`, for a program that calls an adapter the way the engine does — an adapter implements the world's `Guest`, never `Source`), and the embedded prose — `emery_sdk::Doc`, `emery_sdk::prose![..]`, and the lookups `emery_sdk::body` and `emery_sdk::find`. An adapter's `[dependencies]` is `emery-sdk` alone, and it has no `[build-dependencies]`. The mock adapter and the SDK's suites name `emery_sdk::Doc`.
- `emery_sdk::RUNTIME`: the runtime references every adapter shares — `claims.md` (the claim `id` grammar, `path` anchors, the skip roots, and the fail-closed gate) and `reconciliation.md` (the `specify` pipeline and where extracted claims land) — embedded once from `crates/sdk/prose/` and shipped with the SDK, so the guidance that describes the gate moves with the pin of the code that enforces it. `list_docs` lists them after the adapter's own documents and `read_doc` answers them the same way, so an adapter's prompt links `claims.md` as it links the adapter's own references and lists nothing; `emery_sdk::check` is the prose crate's `check` re-exported, and an adapter's suite passes `RUNTIME` as its imports (`check(docs, tree, prompts, RUNTIME)`), so such a link resolves, neither document is required in the tree, and a listed document at either path is a finding. The SDK's `tests/prose.rs` holds `RUNTIME` to its own tree.
- `emery_prose::check(docs, tree, prompts, imports)` takes the imports: documents another table embeds beside this one, which a link may name, which the tree need not hold and no prompt need reach, and which no listed document may shadow.
- `emery_sdk::workspace::list(root, keep)`, the physical workspace traversal an adapter may use: it lists the regular files beneath the root the engine lent, sorted and named relative to it as `/`-separated paths. `keep` is asked about every `workspace::Entry` — `Entry::Dir(path)` prunes a directory, `Entry::File(path)` selects a file — by its root-relative path, which the entry reads for the adapter: `path()`, `name()` (the last segment), `extension()` (after the last dot; a leading dot is not one), and `hidden()` (a dot name), so an adapter's policy is `|entry| !entry.hidden()` rather than its own unpicking of a `Path`. The walk never offers the engine's own files — `.omnia/` directories and `spec.md` / `design.md` wherever they appear — and refuses a name that is not UTF-8 before it is offered. What the adapter does with the files is its own survey policy: `documentation` cuts them into seams, while `intent` uses them only to validate and read its one-file carrier.
- `emery_sdk::survey::surfaces(ctx, docs, keep)`, an optional model-assisted survey helper: one call, before any seam is mined, that finds the surfaces the source exposes — a route, a command, a job, an exported API — each with the module a caller enters it at, rather than grouping the files by where they sit or what they serve. The adapter's `survey.md` among `docs` is the system prompt; the turn, put to the model `ctx` carries, names the adapter and source from `ctx` and lends the root, listing no file — the model reads the tree, and the turn does not grow with the estate; the `list_docs` / `read_doc` tools answer from `docs`. The answer is a `survey::Inventory { surfaces: Vec<Surface { name, entry }> }` — the shape a survey prompt's worked example must parse as — checked whole against the tree: a surface without a name, two surfaces of one name, an entry that escapes the root, one at no regular file, or one the adapter's `keep` refuses under the same `workspace::Entry` policy, with the engine's own files never an entry, goes back as findings and the backend asks again. The surfaces come back in answer order, each entry normalised (`./` and empty segments dropped); a module may be the entry of several, and a module no surface enters is not one, so the model finds the boundary and the adapter mines what each surface reaches from it — there is no floor, no fold, and no remainder. An empty inventory is accepted as the model's answer, and what a source with no surface means is the adapter's to decide. A missing prompt is `server_error` before any turn, as is a survey by model over an inline value — it has no tree; spent rounds are `bad_request` carrying the last findings, as an evidence call's are.
- The tracing level the global `-v` / `--verbose` and `-q` / `--quiet` flags select reaches every adapter a run dispatches, over the dispatch chain's baggage under omnia's `omnia_wasi_otel::LEVEL` entry. `Verbosity::level()` is the `tracing` `LevelFilter` a selection names — `OFF` under `-q`, `INFO` on a bare run, `DEBUG` under `-v`, `TRACE` under `-vv`. The engine names that level on the chain after its own filter reload, and omnia opens each adapter's subscriber at it as the adapter's telemetry initializes — ahead of the extraction's `source_adapter_extract` boundary span, so the span reaches the host at `info` and finer with no reload of the adapter's own. Inside it the SDK maps the level onto the crates the guest owns — the adapter's own crate, `emery_sdk`, and `omnia_sdk` (`DEBUG` is `info` plus the three at `debug`, `TRACE` is `debug` plus the three at `trace`, any other level is itself) — which the adapter's `RUST_LOG` refines after it; the fixed `info` reload is gone, and so is the engine's own `emery.tracing` key. A caller that names no level dispatches an adapter that opens at `error`, as omnia opens any guest; the engine always names one. A level crosses, never directives, so the engine names no adapter crate. An adapter built on an earlier SDK opens at `info` as before; the flags do not reach it.

### Changed

- Extraction is `emery_sdk::extract(ctx, docs, seams)`, called from an adapter's own `extract` with the seams its survey chose. It puts each seam to the model as one turn, at most four pending, then joins the partials into one document: claims concatenated in seam order, every anchor as the model answered it, since every seam is lent the root. Every seam is waited for; the failures are then reported together, each as `- seam <index>: <description>` in seam order, under the first failure's class. No seam is `bad_request` before any is mined. One seam is a single turn and its outcome, unchanged. The turn itself — the embedded `extract.md` as the system prompt, the SDK's brief, the lend, and the claim gate as the check — is the SDK's alone: there is no per-seam hook to call or override, so the seams an adapter hands over are its one way to shape what the model is asked. A survey that asks the model takes the call's `Context`, through `survey::surfaces`; a mechanical survey is a plain fn over the `SourceInput`, and an adapter's suite asserts it with no model at all.
- The SDK is types and functions, the shape of omnia's own guest SDK, and an adapter is a guest of the `source-adapter` world, exported with one macro the way every omnia command guest is with `command!`: its `wasm32`-only guest module invokes `emery_sdk::source_adapter!(metadata, extract)` and writes the two fns it names: `fn metadata() -> AdapterMetadata`, answered with `emery_sdk::metadata(SourceKind::..)`, and `async fn extract<P: Model>(ctx: &Context<'_, P>) -> Result<Evidence, Error>`, which is the adapter's survey then `emery_sdk::extract(ctx, PROSE, &seams)` and nothing else — `let seams = survey::survey(ctx.input)?;` for a mechanical survey, `survey::survey(ctx, PROSE).await?` for one that asks the model — so the flow from cut to turns reads in the adapter's own code and no closure adapts the survey's shape to the SDK's. The `Context` carries the model: the macro's lift binds the host's model, `emery_sdk::Provider` — the unit struct with the empty `impl Model` every omnia guest would otherwise declare, kept in the SDK because an adapter binds the model and nothing else — into every call, so no adapter names a backend; a survey that asks the model is one `async fn survey<P: Model>(ctx, docs)` on every target, and tests build the `Context` with `Scripted` in the field the lift fills. The guest module is `cfg(target_arch = "wasm32")`, so the crate builds natively and its survey is tested there.

- The `Authority` enum is `SourceKind`, the kind of source an adapter reads (`intent`, `documentation`, `behaviour`); "authority" names the precedence those kinds rank by, not a type. An adapter names it in its `metadata` answer through `emery_sdk::metadata`, and a committed requirement's loser notes record it as `kind` — a revision-shape change, so every revision re-ids. The kebab values and the rendered `Note:` lines are unchanged.
- The kind of source is the adapter's metadata, not the document's. The WIT `adapter-metadata` record gains `kind: source-kind` and the `evidence` record is `claims` alone; `emery_adapter::source::AdapterMetadata` gains `kind: SourceKind` and `Evidence` is `{ claims }`, deriving its answer schema with `deny_unknown_fields`, so a document-level `kind` in a model answer is a schema miss the backend corrects. `emery_sdk::metadata(kind)` reports the adapter's kind beside the `emery-version` pin, and the SDK's per-seam turn asks `Question::<Evidence>` directly. `adapter::load` returns each distinct adapter's declared kind keyed by id (`BTreeMap<String, SourceKind>`) from the one `metadata` read that also gates its version, and `specify` ranks every source by it before the fan-out — so an adapter's rank is fixed at load, never read from what the model returned. Committed revisions are unchanged: the loser `kind` a requirement records is the same value, sourced from the adapter.
- `emery-prose` is named for what it does: the `registry` module is gone and `Doc`, `find`, `body`, and `check` sit at the crate root; the `registry!` macro is `prose!`, after `include_str!` — a declarative macro that takes the list of documents to embed, each named from the invoking file the way `include_str!` names one, and expands to the `&'static [Doc]` itself, each body the `include_str!` of its listed file and each table path what follows the file's `prose/` segment, so an adapter reads `pub static PROSE: &[Doc] = emery_sdk::prose!["../prose/extract.md", ..];` at its crate root and looks the document up as `extract.md`; a listed file outside a `prose/` directory fails the build at the list, as a missing one does. Every tree is flat at its root: an adapter's prompts (`extract.md`, and `survey.md` for one that surveys by model) sit at `prose/` beside its `references/`, the SDK's shared references at `crates/sdk/prose/`, and the engine's synthesis corpus at `crates/engine/prose/` — no `prompts/`, `emery/`, or `synthesis/` wrapper holds a whole tree. There is no procedural macro, no `emit` feature, no build-script walker, no generated `docs()` accessor, and no `build.rs`: an edit to a listed file rebuilds the crate through `include_str!`, a listed file the tree lacks fails the build at the list, and `emery_prose::check(docs, tree, prompts, imports)` — the native test a crate's suite runs over the tree beside it, naming the documents its code puts to the model by path — reports a document the list leaves out, a path listed twice, a relative link no listed document answers, a prompt the table lacks, and a listed document no prompt reaches through those links, so nothing is embedded that the model is never told to read; the engine's own corpus is held to the three briefs' `PROSE`. `emery_prose::find` is a scan, so a table is in the order it is listed. `emery_prose::body` returns `Option<&'static str>` instead of panicking on a path the build did not embed — the SDK reads the extraction prompt from the table for each seam's turn and reports a miss as `server_error`.
- The contract and SDK crates are renamed for what they hold. The contract crate is `emery-adapter`, after the `emery:adapter` WIT package it binds, with one public module per axis: `emery_adapter::source::{Source, SourceInput, SourceContent, SourceKind, AdapterMetadata, Evidence, Claim, ClaimKind, Backing, CLAIM_ID_REGEX}` (and, on `wasm32`, `export` — the world an adapter's guest implements, which the SDK re-exports), with the shared kebab predicate at the root (`emery_adapter::is_kebab`). The SDK crate is `emery-sdk`: adapters `use emery_sdk::{Context, Seam, mine, …}` and `emery_sdk::export`; its root stays flat. There is no `emery-source` crate. A second axis lands as a second module in each crate, not a crate.
- The contract crate exposes every public item of an axis from its axis module; the `types` and `claims` modules are gone, as are the test-only `SourceInput::workspace` / `SourceInput::value` constructors.
- `emery_sdk::Context<'_, P>` is `{ adapter_id, input, model }` — the adapter addressed, the input, and the model every turn of the call is put to; `EvidenceTurn`, `content_note`, and the `types` module are deleted; the crate re-exports the contract's types at its root in place of fourteen individual model types; omnia's `model` module is not among them, since no adapter names a model type — `Error`, `Model`, and the error macros are the SDK's whole re-export of omnia. `survey::Inventory` derives `Clone`, `Eq`, and `PartialEq` so a suite can assert a parsed worked example whole.
- `emery-sdk` ships its own `README.md` as the crates.io page, and its docs.rs build targets `wasm32-wasip2` first, so `export`, `Provider`, and the `source_adapter!` expansion are present in the published documentation. `make lint` runs a second clippy pass over the guest side — `emery-sdk`, the engine guest, and the `adapter` example for `wasm32-wasip2` — so a defect in `cfg(target_arch = "wasm32")` code fails `make ci` rather than the live journey.
- The SDK's user turn always offers the `list_docs` / `read_doc` reference tools (every adapter embeds at least its prompt) and describes a bound workspace as "the source tree the prompt walks". The turn names the source by adapter id and key alone; what kind of source it is, the adapter's own `extract.md` says, so the SDK carries no source noun.
- `specify` checks its source list whole — non-empty, kebab-case keys, no key twice, roots beneath the project — before a single adapter loads, so a refused list never fetches a package or reads a component.
- `specify` ends the run as soon as a source fails, and the failure is the run's as the adapter put it — code and description: a refusal of its input is `bad_request` (exit `1`), an upstream failure `bad_gateway` (exit `4`) — where before every source was waited for and every failure, a refusal included, was flattened into one `server_error` (exit `3`). Evidence the claim gate rejects is still the engine's `server_error`.
- `emery_sdk::extract` reuses a slot as soon as any turn answers rather than once the earliest pending one does, so a slow seam no longer holds finished slots idle behind it; the document still reads in seam order. Seams are dispatched largest first — a `Files` seam by its file count, a `Whole` or `Note` seam, whose size is not known, before them in seam order — so the small seams fill the slots the large ones leave. A seam whose turn fails upstream (`bad_gateway`: the model or a tool transport) is put once more before the source fails, and the retry's outcome stands in for the first; a refusal — the host's, or the gate's once the rounds are spent — is never retried.
- `emery_sdk::CONCURRENT` is documented as a cap on the turns in flight, not on how finely a survey cuts: a finer cut packs the slots better even though no more than four are answered at once.
- The SDK's instrumented source-adapter boundary initializes and flushes guest telemetry around extraction, and opens the guest's filter at the level the run's `-v` / `-q` flags selected (`info` on a bare run, so an adapter's progress reaches stderr beside the engine's); the process `RUST_LOG` refines it, as it does the engine's. The SDK's events take the engine's shape — INFO as a slow step opens, DEBUG for what it yielded — and every one names the source key and, within a seam, its index, since the guest console prints no span fields: `surveying` and `mining` (per seam, with the file count where a `Files` seam knows it) at INFO; `surveyed` (with the surfaces found), `mined` (with the claim count), every reference-tool call (`answered`: the tool, its arguments as the model sent them, and the refusal if any), and every `candidate rejected` (with its findings) at DEBUG; a turn put once more (with the upstream error, which nothing else reports) or `failed` (with its class alone) at WARN. The engine brackets each source with `extracting` at INFO and `extracted` at DEBUG, the latter carrying the claim count. No description is printed twice: the failure body on stderr is its one print, so neither the engine's spans nor the SDK's record an error as an event.
- The global `-v` / `--verbose` and `-q` / `--quiet` flags set the engine's tracing defaults (`Verbosity::directives()`, a plain `RUST_LOG` string per level), and the guest telemetry layer applies the process `RUST_LOG` after them: its valid directives win for a target both name and a bare level in it replaces the flag's, `-q` included, where before `-q` ignored the environment; an invalid directive is reported on stderr and ignored rather than failing the reload. `Verbosity::into_filter` and its `Display` are gone.
- An adapter's identity is its reference. `AdapterRef`'s `Display` / string conversion — a bare name, a project-relative component path anchored where it was written, or a `<namespace>:<name>@<version>` package reference — is what the plugin loader registers the adapter under and what the `Source` capability dispatches to; `AdapterRef::name`, `AdapterRef::id`, and `adapter::Loader` are gone: `adapter::load(provider, adapters)` takes the references a run's sources name, loads every distinct adapter once — all together, so a run waits only for its slowest acquisition — and reads each one's `metadata` once, however many sources share it — the `emery-version` gate, and the kind of source it returns keyed by adapter id. The `source:<name>` routed id is gone with them: a bare `intent` dispatches to the deployment's guest `intent`, and a local component is registered under its path, so two files sharing a stem are two adapters rather than one. The kebab stem a command-line adapter is keyed by when the operator names no key (`emery_intent.wasm` → `intent`) is the CLI's rule, beside the argv decoder in `crates/cli/src/sources.rs`.

### Removed

- `emery-prose-macros` and `emery_prose::include_prose!` are gone. A corpus is listed with `prose!` and held to its tree by `check`, so no crate carries a `build.rs` for its prose.
- `emery_sdk::SourceAdapter` and the `source!` macro are gone, and with the trait its `extract`, `evidence`, `prompt`, `metadata`, and `stamp`. An adapter's `extract` is its own plain fn — its survey then `emery_sdk::extract` — named to `emery_sdk::source_adapter!` beside its `metadata`, which is `emery_sdk::metadata(SourceKind::..)`; the `doc(hidden)` on `export`, which the trait's macro expanded against, is lifted. `emery_sdk::Answer` is gone too: the model answers the contract's `Evidence` directly, and there is no kind to stamp onto it — the engine takes it from the adapter's metadata.
- The per-source `digest` pin (`SourceConfig.digest`, `[[source]] digest`) is gone. A local component or exact package reference loads without a content hash; a `digest` key in `emery.toml` is an unknown field.
- The per-source `registry` override (`SourceConfig.registry`, `[[source]] registry`) is gone: which registry serves a package is the deployment's policy, not a project file's, so no `emery.toml` can redirect the binary. The shipped runtime resolves a package's namespace through a wasm-pkg client configuration compiled in beside its default endpoint (`src/wasm-pkg.toml`, the schema of `wkg`'s own config, embedded by `src/main.rs` as `{ registry: "omnia.host", config: include_str!("wasm-pkg.toml") }`); `emery:<name>@<version>` routes to `augentic.io`, anything unmapped to `omnia.host`. Every package load carries `Location::Registry(None)`; a `registry` key in `emery.toml` is an unknown field.
