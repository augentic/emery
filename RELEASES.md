### Changed

- An adapter declares itself through `metadata()`. `emery_sdk::SourceAdapter::metadata() -> Metadata` answers `Metadata { kind }` in place of `const KIND`, and `emery_sdk::target::TargetAdapter::metadata() -> target::Metadata` answers `Metadata { rules, grants }` in place of `const MERGE_RULES` and `const WORKER`, `Metadata::default()` by default, each adapter spelling the values as module-level `const`s; `export_source!` and `export_target!` answer the component's `metadata` over them, and `target::call` carries the `grants` into `BuildContext` and `VerifyContext`. `target::Reach` is `target::Grant`, and `target::Worker` is gone: a turn's grants are a plain `&[Grant]`, `Grant::union(grants)` the `WorkerGrant` they unite to, `None` when they unite to nothing, and `Grant::findings(grants)` the shape gate, so `BuildContext` and `VerifyContext` carry `grants: &[Grant]` in place of `worker: &Worker`.
- Where a build lands is the `[target] repository`'s to say, and the adapter declares no base. A `repository` is a URL, built into a clone of it from `origin/HEAD`; `"."`, the project checkout from its sealed head, where a build with no `repository` landed before; or absent, a repository the engine lays once at `.emery/vcs/repos/<name>` and keeps, so `emery build <adapter>` on the command line lays one with no precondition on the project directory. The adapter no longer says which: `target-metadata.base` and `emery_adapter::target::Base` are gone, `TargetAdapter` has no `BASE`, and `target::metadata(merge_rules)` takes the rules alone, since `Task::Init` lays only the files a tree lacks and leaves a held one as it stands, so a base holding a directory is nothing to refuse — `base-not-fresh` is no code — and the project checkout is never written unless named. `BUILD_DESC` and the `repository-required` hint state the three forms; `examples/emery.toml` names `repository = "."` so the live journey still lands in the scratch project; `EMERY_MOCK_FRESH` and `EMERY_MOCK_FRESH_TARGET` are gone with the second mock build.
- A module-level table is a `type` claim as a class field's is. `BindingKind::Value` gains `table: Option<String>`, the declaration whole where an adapter's parser found the initializer a table with at least one entry, and `survey::types` answers one claim per exported module-level value carrying one within `TABLE_LINES` — its text less its blank lines as the signature, `exported table` as the synopsis, anchored at the binding's lines over a workspace — so a constant mapping the code reads reaches the design with its entries rather than as a name a build fills in.
- `BuildOutput::verified` names each wave's slices. Each entry is a `Verified { wave, slices, head }` — the wave from one, the slice ids merged in it in id order, those this run built and those an earlier run staged, and the integrated head it was verified at — where it was the head alone, so text mode pairs every wave block with its slices by the wave rather than by position and prints `    <id>: staged by an earlier run, not built again` for a staged slice beneath `  wave k: n slices verified at <head8>`; `resumed` lists the staged slices beside the label's. The `verify-failed` hint says the next run verifies the wave's merged slices again with nothing built, or rebuilds the wave from the last verified head once the copy is removed with `git worktree remove --force`; the `bad_gateway` hint names the integration copy beside the label. The JSON shape is in [CLI output shapes](docs/reference/cli-output-shapes.md#emery-build).
- `SLICE_CAP` is 12, where it was 20. The first live `omnia` build timed out on a slice of fifteen requirements, the turn spent composing, so a stem is floored at its sub-stems past twelve and the slicing gate's pair rule cuts it to slices of up to twelve. `tests/specify.rs`'s `oversized_stem` and `oversized_stem_cut_fine` read the const and hold.
- The specification states what the system does for those it serves; the design holds how it readies itself. `claims.md`'s "Behaviour, not technology" is rewritten around one rule, served to every adapter's extraction turn: a `requirement` states what the system does for those it serves, or what they observe when it cannot, and how the program readies itself, reaches another system, or recovers — a credential or token loaded, cached, or rotated; a reference table prefetched or refreshed on a timer; a client, pool, or connection constructed; a consumer subscribed; a readiness helper wired over internal clients; a heartbeat log; a signal or uncaught-error handler; a drain or exit delay; a retry rule, backoff, or timeout; a delivery acknowledged; a span opened; an error caught and logged — is the design's, carried by `excerpt` and `call` claims and never by a `requirement`; what survives under `start` is the rule applied to every request, the health route the program itself states, the setting it refuses to run without, and the caller-visible face of an upstream call. Beside it: a helper is a requirement where a build must reproduce its arms, formula, or constructed shape and folds into its caller's decision where it is only that decision's condition or a single-caller lookup; a statement and a scenario use the domain's words (`OVERDUE_DAYS`, `YYYY-MM-DD`, `an Order`) and never an identifier only the code spells (`Config.useTls`, `fetchRates`, `orderRow.createdAt`). The survey carries the same rule into every brief: the `start` surface's note says the bootstrap is claimed for what those the program serves observe of it as a whole and that its readiness, its reach, and its shutdown are the design's; the decision-points heading no longer makes what `start` constructs with a boundary's value a requirement, so a line that only wires, assigns, or constructs a client or a connection is no requirement's anchor; the calls heading has every listed call that leaves the process be a `call` claim with a `requirement` beside it where what the caller observes depends on it, where it had every such call carry a requirement; and the stated-behaviours heading has the tree's own test's sentence lead the statement with the code's identifiers standing nowhere in it. The facts no longer list the modules only the bootstrap reaches as surface candidates: an upstream client, a secret retriever, or a gateway is a mechanism reached through the bootstrap or the surface that uses it, so it lands in `start`'s closure and the design rather than as a surface and a slice of its own (`Located::services` and `crates/sdk/tests/seams.rs`'s `services_listed` are gone; `whole_tree`, `bootstrap_runs`, and `tree.rs`'s `start` assertion carry the new note).
- `slicing.md` defines a build dependency. A slice depends on another when its code cannot compile or test without it — it uses the other's design types, or edits its files — and what it assumes of the running system (a client another slice constructs, a consumer subscribed, a server listening, an event another slice publishes) is no dependency and goes in the brief, since every slice of a wave builds at once and each dependency named serialises a build. The worked example's `order-notifications` depends on nothing and states the event it assumes, where it had depended on `orders`; the first live plan had chained every slice.
- The build compiles the compiler only where something runs it. The release legs of `publish.yaml` run `emery --help` from the built binary before packaging it, the first load of the precompiled guest, so a compile-option or wasmtime-version mismatch fails the leg rather than shipping.

The map reading admitted it as two files named `path` and `content` and accepted the call; a map with a `path` key is now the one entry the schema declares for a list item, held to those two keys — a missing `content` or a stray key is malformed as a listed entry would be. `crates/sdk/tests/build.rs` gains `write_object_shape`.
- The SDK's export macros are named for what they do: `emery_sdk::export_source!(Adapter)` exports a `SourceAdapter` as the `source-adapter` world and `emery_sdk::export_target!(Adapter)` a `TargetAdapter` as the `target-adapter` world, in place of `source_adapter!` and `target_adapter!`, which read as declarations beside the `impl` they follow. - Every adapter is a package, read from a store. An adapter — a positional `<adapter>`, a `--description <adapter>=<text>`, a `[[source]] adapter`, the `[target] adapter` — is an exact package reference, `namespace:name@version`, and every reference loads through the `omnia:plugins/loader` capability at its registry location, which omnia resolves store-first: the shipped runtime's `plugins: { store: "~/.emery/adapters", registries: include_str!("wasm-pkg.toml") }` names the package store, where a release is one file filed flat by its reference as `namespace_name@version.wasm` — the name `wkg get <reference> -o <dir>/` writes, so `ls ~/.emery/adapters` lists references — read fresh on every run and with no network, whoever wrote it, the fetcher, an operator's `cp`, or `wkg get`, and final until removed; a release the store lacks is fetched from the registry the binary routes its namespace to, hashed to the registry's digest, written to the store once, and loaded, so the first run on a fresh machine that names a release is one fetch and every run after reads the file. The routing is compiled in and nothing on the machine redirects it: `src/wasm-pkg.toml` is `[namespace_registries] emery = "augentic.io"` alone, and a release the store lacks under any other namespace is the loader's `refused` (exit `1`) before any fetch, naming the namespace and the file the store holds no copy of, with the one static hint `wkg get <reference> -o ~/.emery/adapters/` — the command that fills the store under wkg's own routing and the mirror recipe for a machine that must not fetch — where the engine names no registry on a load (`Location::Registry { endpoint: None }`), so a project file, which a build can rewrite, chooses which package and, through `digest`, which bytes, and never where from. A registry that cannot supply a release is `unavailable` (exit `4`), and a copy in the store stands in for it. A copy at a published version stands in for that release on this machine, for every project naming it — the operator's trust the store is, as `~/.cargo/bin` is — and a developer's build is kept beside the release under a version of its own, by convention a `-dev` pre-release (`emery_typescript@0.14.0-dev.wasm`, named `emery:typescript@0.14.0-dev`). The store holds raw wasm alone: a `.cwasm` copied in, or served by a registry, is refused however it hashes. There is no default namespace, no latest, and no machine-wide active release; `emery adapter …` is a clap usage error (exit `64`), since the store is a directory and the shell is its tool. The first-party train publishes to `ghcr.io/augentic/emery/<name>:<version>`, which is where `augentic.io` resolves `emery:<name>@<version>` to.
- The mount and the store follow W^X — what a run can write it never loads code from. The invocation directory is the one mount, `.`, writable where it was read-only: the tree `specify` lends its source adapters and `build` lends its target, `.emery/storage` beneath it. The package store `~/.emery/adapters` is no mount at all — the host's loader reads it and no guest reaches it — and lies apart from any project, so a component is never loaded from a tree a run can write; omnia refuses a store beneath a writable mount when the deployment assembles, so running `emery` from `$HOME` itself is refused at startup. A build lends the whole project tree, `.emery/` included — the revision store fails closed on a document rewritten beneath it rather than preventing the write — and an extraction turn's lend is unchanged in path and brief, now over a writable mount.
- The engine's root under a project is `.emery/`, where it was `.omnia/`: revision state lives at `.emery/storage`, and `emery_adapter::SKIP_DIRS` names `.emery` beside `.git`, so a claim anchored or a file written under either is refused — `is under the reserved `.emery/`` — and `emery_sdk::workspace::list` offers neither. A `.omnia/` left by an earlier build is orphaned: nothing reads it, and a `specify` must be re-run to commit a revision under the new root.
- `crates/cli/src/sources.rs` is `config.rs`: the one module carrying every `emery.toml` table — `[[source]]` for `specify`, `[target]` for `build` — and the argv carriers of each verb, every `adapter` parsed as an `AdapterRef` at the field. Each verb's carriers decode in one flat match (`SourceCarriers` into `SpecifyInput`, `TargetCarriers` into `BuildInput`), and `ConfigFile` is one plain struct read whole: every table must parse for any verb to read the file, as Cargo reads its manifest, so an unknown key or a malformed `adapter` under `[[source]]` refuses a `build` and one under `[target]` refuses a `specify`, where each verb decoded its own tables and skipped the rest. A `[[source]]` entry that parses is still located only by the run whose source it is, so an escaping `path` among them never refuses a run that named its own sources. A `[[source]]` entry without `name` is keyed by its package's name, as an argv source is.

The `Context` carries the model: the macro's lift binds the host's model, `emery_sdk::Provider` — the unit struct with the empty `impl Model` every omnia guest would otherwise declare, kept in the SDK because an adapter binds the model and nothing else — into every call, so no adapter names a backend, and tests build the `Context` with `Scripted` in the field the lift fills. There is no procedural macro, no `emit` feature, no build-script walker, no generated `docs()` accessor, and no `build.rs`: an edit to a listed file rebuilds the crate through `include_str!`, a listed file the tree lacks fails the build at the list, and `emery_prose::check(docs, tree, prompts, imports)` — the native test a crate's suite runs over the tree beside it, naming the documents its code puts to the model by path — reports a document the list leaves out, a path listed twice, a relative link no listed document answers, a prompt the table lacks, and a listed document no prompt reaches through those links, so nothing is embedded that the model is never told to read; the engine's own corpus is held to the four briefs' `PROSE`. `emery_prose::find` is a scan, so a table is in the order it is listed. `emery_prose::body` returns `Option<&'static str>` instead of panicking on a path the build did not embed — the SDK reads the extraction prompt from the table for each seam's turn and reports a miss as `server_error`.

- The claim gate checks a `path` anchor's grammar: `emery_adapter::source::Anchor::parse` reads `<path>[#L<n>[-L<m>]]` — a path `emery_adapter::beneath` accepts, and a line range with no leading zero whose end is not before its start — and `Evidence::findings` names each malformed anchor (`BadAnchor`) beside the id and extras findings, so a claim anchored at `../secret`, `.emery/storage/x`, or `src/a.ts#L9-L3` is refused before any requirement is built from it. `beneath(path)` is the one root-relative path rule, at the contract crate's root beside `is_kebab` with `SKIP_DIRS` and `SKIP_FILES` (moved up from `emery_adapter::source`): it answers the path normalised — `/`-separated, empty and `.` segments dropped — or the `BadPath` it breaks (`Escapes` for an empty, absolute, or `..` path; `NoFile` for one naming the root itself; `SkipDir` under `.emery/` or `.git/`; `SkipFile` for a `spec.md` / `design.md` / `plan.md`), rendered as `escapes the root`, `names no file`, `is under the reserved `.emery/``, `names the engine's own `spec.md``. `BadAnchor::Path(BadPath)` carries it, where `BadAnchor` spelled `Escapes`, `SkipDir`, and `SkipFile` of its own with `escapes the source root` and `is under the skip root`; the report gate holds every `written` path to the same rule, where it had its own with `escapes the workspace root` and no skip-file check, and lists a file twice however the two spellings differ; the SDK's seam files and survey anchors go through it too, where the SDK kept a third copy. `Claim::anchor()` reads a claim's parsed anchor for a caller that checks it against a tree, as the SDK's extract does.
- `emery_sdk::extract` verifies every anchor and id against the seam that minted it, and its `check` hands the model the findings as corrections: a `path` on an inline value's claim (no tree was lent), a `path` outside the files the seam names, a `path` at no regular file under the lent tree, or a `#L` line past the file's last; a `requirement` or `criterion` id whose first segment is not one of the seam's `stems`. A seam's files are laid in the turn whole when they fit — `emery_sdk::INLINE_BYTES` (64 KiB) across the seam — every line led by its number so `#L<n>` is cited from what is shown rather than re-read (`### \`file\` (N lines)` and a fence per file), and listed by path otherwise; `Seam::stems` carries the stems the seam's ids must lead with, so an adapter's survey binds each seam to its surface. `claims.md` states the path and stem rules the gate enforces.
- `GroupingBrief::derive` asks the model to group whenever one source's requirement ids span two or more stems, not only when two or more sources are bound: one source's seams may describe one behaviour under different nouns, and the baseline's id-equality never merges those. A single-source, single-stem run still spends no grouping turn.
- A design `type` block is keyed by the claim's declared name — its id, its `name` extra, or its path with any `#L…` anchor stripped — where a path-keyed claim carried its anchor, so re-anchored runs churned the revision id. A name an earlier claim took gains the later claim's anchored path in parentheses, so two declarations of one name are placed apart.

### Removed

- `[target] branch` and `[target] remote` are gone from the grammar, not aliased: each is an unknown field, refused with its name and line. A build is never pushed, so `BuildOutput.pushed`, the `  pushed to <remote>` line, `Repo::push`, `at_push`, the `label-diverged` recovery code and its hint, and the engine's reading of a remote's label (`Vcs::fetched`) are gone with them; the `Diverged` error, which only a push raised, maps to `server_error`. The push is the operator's, from the repository the envelope names.
- `emery_cli::Verbosity` is gone: the `-v` / `--verbose` and `-q` / `--quiet` flags are omnia's, declared through `omnia_sdk::api::command::Verbosity` and read by the runtime, never by the engine. The subscriber `execute_wasi` installs is the engine's filter, over the `RUST_LOG` the runtime sets.
- `emery-prose-macros` and `emery_prose::include_prose!` are gone. A corpus is listed with `prose!` and held to its tree by `check`, so no crate carries a `build.rs` for its prose.
- The `source!` macro is gone, and `emery_sdk::SourceAdapter` keeps `extract` alone of its methods: `evidence`, `prompt`, `metadata`, and `stamp` are gone, the kind `metadata` answered is the trait's `const KIND`, and the type implementing it is exported with `emery_sdk::source_adapter!(Adapter)`. An adapter's `extract` is its survey then `emery_sdk::extract`; the `doc(hidden)` on `export`, which the trait's macro expanded against, is lifted. `emery_sdk::Answer` is gone too: the model answers the contract's `Evidence` directly, and there is no kind to stamp onto it — the engine takes it from the adapter's metadata.
- The per-source `registry` override (`SourceConfig.registry`, `[[source]] registry`), the `[registries]` table, and `emery_engine::Registries` are gone; a `registry` key on a `[[source]]` and a `[registries]` table are unknown fields, refused with their name and line. Where a release is fetched from is the binary's compiled-in route (`emery` to `augentic.io`) and otherwise the operator's `wkg get <reference> -o ~/.emery/adapters/`; `~/.emery/wasm-pkg.toml` is not read — a file there from an earlier 0.38 build is inert and may be deleted.
- Bare names and component paths are gone from every adapter position: `AdapterRef::File` / `AdapterRef::Static`, `Location::Path` / `Location::Declared` loads, the `.wasm` and kebab heuristics, the stem rule (`my_adapter.wasm` → `my-adapter`), `file://`, the `NAMESPACE` shorthand (`intent@1.0.0` for `emery:intent@1.0.0`), `emery_engine::ADAPTERS`, `emery_engine::ENGINE`, and the engine's refusal of a reference naming its own guest (a package id always carries a colon and the engine's is bare, so the collision is structural). The shipped binary declared no adapter, so a bare name always refused; now it is `bad_request` with code `adapter-reference` before any load, as a path is. A component an earlier 0.38 build read from `~/.emery/adapters/<name>.wasm` is never read again: `mv ~/.emery/adapters/name.wasm ~/.emery/adapters/<namespace>_<name>@<version>.wasm` keeps one still wanted, under the reference a project names it by (a developer's build under a `-dev` version of its own), and `rm` drops one the next run may fetch.
- The reserved `git` and `url` content keys are gone; each is an unknown field, refused with its name and line like any other. The `[[source]] name` key is optional: an entry naming none is keyed by its adapter, as an argv source is.
