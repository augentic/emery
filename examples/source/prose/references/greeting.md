# Greeting source

The mock source documents one behaviour: GET /greeting returns the static string 'hello'. Its requirement id stays `greeting.behaviour`. A criterion id extends that id (`greeting.behaviour.body`) when the bound tree states acceptance. A brief that adds a behaviour of a concept it introduces takes a stem of its own (`throttling.limit`), and a directive prescribing a technology for it is a `decision` beside the `requirement`, never part of its id or statement. A `requirement` states what the service does for those it serves, never the directive's own content: a brief whose whole content is the technology behind a behaviour the service already has is a `decision` alone, and a brief about a concept the service already has stays under that concept's stem (`audit`, never `audit-log`).
